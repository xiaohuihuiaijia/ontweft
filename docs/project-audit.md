# 项目审查与优化记录

日期：2026-11-11。基线：`a4c36f8`，企业 Beta 分支。以具体故障、重复行为和维护成本为依据，保留“轻核心＋按需扩展”。

## 覆盖与方法

逐模块阅读全部后端和前端自有实现、27 个历史迁移、Java CDC 适配实现、部署/开发/验证脚本、示例及使用文档；核对入口、注册引用与调用契约，精读受影响测试并运行回归。锁文件、生成通知与协议夹具按依赖/合同用途核对，不声称逐行审计第三方源码或每个历史测试。已复现的问题先补行为测试，再做最小修复。

本轮只用合成内容、隔离 SQLite/PostgreSQL 和本地模型替身。没有读取业务数据库、真实环境文件、私有 PDF 或识别结果，没有付费模型调用。没有新增运行时依赖、数据迁移、常驻服务、插件平台或审批系统。不能由本次审查推断“所有缺陷已消除”。

2026-11-10 的审查和优化保留在[历史记录](https://github.com/xiaohuihuiaijia/ontweft/blob/a4c36f82fbe6b37b339d3828d48bfe64a001b7bf/docs/project-audit.md)，不混作本轮结论。

## 已修复的确定问题

| 问题与影响 | 本轮处理 |
| --- | --- |
| 未发布模型时，来源采集完成却因不存在的发布版而失败 | 无映射时正常保存原始快照，不凭空建对象 |
| 无关来源目录变化阻断正常快照或 CDC | 运行时只验证本来源/资源映射；模型发布仍全量验证 |
| 模型匹配语义改变，持续规则继续用旧索引，可能错误撤回关系 | 仅在匹配语义、目标或基数改变时复用现有重建队列；标签变化不重建，人工支持保留 |
| 手工对象/关系引用未保存规范化解析版本 | 保存现有引用校验的返回值；新证据固定历史版本，不改写旧证据 |
| Office/文本重解析改变逻辑页，AI 缓存、续跑和原文跳转混用版本 | 提案固定解析快照，缓存绑定实际输入；版本标识贯穿候选、审阅、正式导入和原文图片接口 |
| Word 图片遗漏或错误标为完整理解 | 原生图片保留待复核状态；为历史/可选 Docling 结构补原件中的图片引用，不猜测图片与段落的对应关系 |
| 大文档每页重复全文摘要、重解析一次读入全文件 | 每任务每份原件核对一次；请求仍核对原件，重解析流式计算摘要并使用当前限制 |
| 恢复后 PDF 断点缺失，到解析末尾才发现 | 继续处理前核对已有批次，立即报告缺失；从文档重新提交解析，不伪造已完成页面 |
| 非有限 JSON 可落库后导致响应或后续列表 500 | 在现有属性转换与模型结果边界统一拒绝 NaN/Infinity/溢出；合法 JSON、大整数行为保留 |
| 对象列表和知识图谱反复读取同一模型/完整文档 | 复用请求内定义；联查发布字段并分批读取文档元数据，保持权限和画布预算 |
| 撤权后旧候选/图谱/来源样本仍显示，晚响应覆盖当前选择 | 清除被拒绝内容、作废过期请求；复用现有资源加载方式，不加全局状态系统 |
| 候选保存期间输入丢失、模型参数切换丢输入、任务详情状态滞后 | 保存时锁定相应输入，保留未完成参数文本，任务详情跟随当前记录；异步校验仍显示校验阶段 |
| AI 材料/提案与对象关系只有首批记录可访问 | 沿用现有列表增加分页、稳定次排序及总数，材料选择跨页保留；不建设新搜索模块 |
| 三份权限列表漂移，压测权限比正式运行更宽 | 四处使用现有注册模块的同一授权函数；撤销过时权限，AI 页面结果只读/追加 |
| 本机文档入口仍为 25 MiB，和核心 256 MiB 不一致 | 统一文档体验上限；26 MiB 合成上传回归通过。确定性表格的独立容量预算保持明确 |
| 小规模压测参数导致不存在的目标、重复关系或空统计报错 | 修复夹具目标选择和参数边界，按实际请求生成统计；完成小夹具查询、校验及并发传播 |
| 无效任务状态、未用样式和过时使用文档 | 删除确认无引用项；修正默认 Word 测试、导航/点击操作、计费与恢复说明；更新真实截图和中英文首页 |

同一条件在执行前重新鉴权、版本比较、数据库约束、任务租约与幂等处理不同状态变化，保留这些机制。没有为减少行数删除公开 API、历史迁移、已发布函数、历史数据或来源证据。

## 剩余事项，供审核

| 优先级与事项 | 当前边界 | 建议的最小下一步 |
| --- | --- | --- |
| P1 · 复杂材料的事实质量 | 有来源不等于内容正确；独立原文标注、准确率及整本视觉理解未验收 | 先完成既定代表页金标准和错误分类，再决定局部提示/模型调整；沿用原预算，不默认增加 OCR |
| P1 · 大规模与持续负载 | 既有唯一编码搜索 P95 2.135 秒未达目标；大批快照仍持项目写锁 | 在专用参考环境测真实数据分布、首次导入和锁等待，再优化已确认瓶颈；不先加缓存或额外数据库 |
| P1 · CDC 与灾难恢复实演 | 合成窗口通过不等于真实 WAL 过期/新复制槽/重建基线通过；大附件恢复未测 | 用隔离真实 PostgreSQL＋Debezium 演练，保留当前窗口预算与现有恢复工具 |
| P2 · 历史数据修复范围 | 旧证据可能无解析版本，旧 SQLite 也可能已有非法 JSON；本轮未读取业务库，数量未知 | 先对获授权的存量只读统计，再人工核对可恢复引用；不猜测历史版本或静默改成 null |
| P2 · 复杂 Office 内容 | SmartArt、矢量组合和不支持的嵌入图片不等于完整视觉页；可选 Docling 实机本轮未装 | 优先将具体失败文件导出 PDF 复用现有视觉流程；只有实际需求成立才加可选转换 |
| P2 · 长 AI 作业与候选量 | 同 worker 顺序处理页面；累计候选仍存 JSON；取消后未知费用保守预留 | 用公开大样例测排队、写放大和审阅响应；先调整现有 worker，确有需要再补候选分页或费用对账 |
| P2 · 交互与容量取舍 | 目标候选最多 100 条并提示缩小搜索；多层非模态侧栏未统一焦点策略；表格/CDC 各有容量预算 | 先确定高连接度对象、键盘用户及大批导入场景；沿用当前组件与分页，不整体换 UI/图谱引擎 |

迁移账户也有明确边界：默认 Compose 迁移使用拥有跨租户读取能力的数据库所有者。历史数据回填依赖该能力，未宣称任意普通 NOBYPASSRLS 外置迁移账号可直接替代。AI 表的部分外键为单 ID，跨项目引用由现有服务授权与来源校验约束；本轮没有发现可复现绕过，也未为此增加无依据迁移。
