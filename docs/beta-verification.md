应用与独立 HTTP 客户端运行于 Windows；单个 API 服务使用 4 个 Uvicorn 进程。数据库为 Docker Linux PostgreSQL 17.11，受限 NOBYPASSRLS 角色、强制 RLS；Docker 可用 6 CPU、约 11.68 GiB。不是计划中的专用 8 vCPU／32 GB 参考机，也不代表最低安装配置。

合成夹具为 **100,000 个对象、1,000,000 条关系、50 个用户**。50 个并发客户端共执行 1,000 次查询，每类 250 次；另记首轮同时发起的 50 次唯一编码搜索。首次接入与全文／匹配索引由夹具预建，不作为导入或全量建索引吞吐证明。

| 请求 | P50 | P95 | 对照 1 秒目标 |
| --- | ---: | ---: | --- |
| 唯一编码全文搜索 | 0.513 s | **2.135 s** | 未达到 |
| 常见词搜索（命中全部 10 万对象，返回一页） | 0.417 s | 0.765 s | 本夹具达到 |
| 邻域分页 | 0.397 s | 0.772 s | 本夹具达到 |
| 对象详情 | 0.337 s | 0.657 s | 本夹具达到 |

上述 1,000 次查询与额外首轮 50 次请求均成功，结果断言通过。首轮 P95 为 **2.713 s**，未隐藏为预热。客户端每轮依次请求各类接口，首个测量轮也是 50 路唯一编码查询；不能用其他接口的低延迟代替这一突发查询结果。

实际授权 SQL 执行计划：唯一编码分页约 0.278 ms；常见词分页约 0.479 ms，使用当前对象排序索引。修复了 PostgreSQL 无法把查询的 `IS FALSE` 与旧索引条件 `= false` 对应的问题，常见词不再全表排序。SQL 时间只是一次执行计划采样，不是端到端 P95。交互明确使用 `count_total=false`，返回一页和 `has_more`；旧 API 默认精确总数保持兼容。

## 持续传播与后台任务

10 万对象模型校验完成 **402 批、83.37 s**，结果有效。20 次顺序对象修改同时传播到全文检索和持续关系，P95 为 **0.541 s**。

并发测试使用已就绪的独立真实 worker。50 个用户同时修改不同对象，全部写入被接受，全部最终同时满足全文检索与规则关系断言：

- 从发起写入到两处可见，P95 **22.420 s**、最大 **22.446 s**，包含写入等待、查询重试和观察间隔，本夹具达到 30 秒目标。
- 写入响应 P95 **15.792 s**；worker 冷启动另记 **2.922 s**。
- 观察器每秒查询，先确认全文结果再查邻域。期间 **25 次查询返回临时 503 并重试**；不是“所有观察请求一次成功”或持续可用性验收。
- 结束时待索引请求为 0，关系待处理队列为空。

复测前已修复索引持续跳过繁忙项目造成的饥饿：现在短暂加入项目锁队列，超时保留任务，不把正常竞争记成索引损坏。分词器初始化在 worker 启动时进行。Windows 压测会清理自己的整个进程树；曾受残留进程、共进程 worker 或错误只读写入账号影响的诊断批次不用于当前验收表。

快照投影另有 1,000 条合成记录的 SQL 对比：首次投影总语句 23,013 → 20,012，重复采集 15,013 → 12,012；每批发布模型读取 1,002 → 1，身份读取 4,001 → 2,001。该采样不能证明 10 万条首次导入速度；最终投影仍保持整批原子提交和项目写锁。

## 部署与恢复

最新源码镜像的 Linux Compose 小夹具验证通过：production 配置、Secure Cookie、受限角色、异人审批、真实 worker、健康／任务指标、独立空库／空卷恢复、原始文件字节一致及临时文件排除。备份 **1.50 s**，恢复到可登录并读取对象／原件 **17.55 s**；夹具含一个对象和一份实际 CSV。

此前同日完成过 10 万对象／100 万关系的隔离恢复：备份 9.24 s、恢复 61.94 s。该历史规模夹具也只有一份 CSV，本轮没有重跑规模恢复，不能外推大体积附件库、真实灾难 RTO 或生产 RPO。RPO 仍取决于部署者实际执行的备份频率。

## 复现与尚未验收

先提供专用测试 PostgreSQL 的 `ONTOLOGY_TEST_ADMIN_URL` 与 `ONTOLOGY_TEST_RUNTIME_URL`；不要指向生产库。规模工具创建并删除随机独立测试库，保留结果报告：

```sh
python scripts/beta_benchmark.py --objects 100000 --relations 1000000 --users 50 --workers 4 --common-queries --concurrent-writes
docker build -t ontweft:beta-test .
python scripts/verify_deployment.py
```

本轮原始记录位于忽略目录 `var/reports/remaining/`，最终规模报告为 `verified-benchmark.json`。脚本退出成功表示请求结果及传播断言完成，不代表所有延迟目标达标。

仍需保留的限制：

- 唯一编码搜索 P95 与首轮突发查询未达 1 秒；并发写入时仍有临时查询拒绝。正式性能验收还需专用参考环境、持续负载、真实数据分布及针对实际瓶颈的调优。
- 10 万对象首次采集／建索引与大批量原子投影的持锁时长未完成规模验收；没有引入分批可见层或额外基础设施。
- CDC 重建通过 SQLite／真实 PostgreSQL 和原生事件夹具；真实 Debezium 的 WAL 过期、新复制槽及重新基线端到端演练尚未完成。10,000 事件／64 MiB 原子窗口预算保留。
- 大体积附件恢复、真实飞书员工授权／外发、复杂 OCR、完整 OWL／SHACL、推理／向量／自然语言能力分别配置、分别验收。
- 商标清查、完整安全审计和所有第三方二进制／模型包再分发验收未宣称通过。
