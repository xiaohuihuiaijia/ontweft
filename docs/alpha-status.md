## 发布前已有验证

2026-11-09 的开发工作区完成前端 146 项、对象/模型/平台后端 115 项（另 44 项因环境条件跳过），独立 SQLite/PostgreSQL 模板与图谱工具 10 项；这些组有重叠，不能相加为一次全量。

真实 Chromium 走通模板自定义、模型保存/校验/批准/发布、对象与关系、图谱选择、自环/平行/反向关系、手机触摸、对象编辑后刷新持久化。所有演示均为合成数据。

独立 501 节点/1100 关系样本中，500 节点请求由 508 条 SQL 降为 8 条；本机服务端 P95 约 105ms。Windows/i5-10200H/16GiB、SQLite 单用户及软件 WebGL 的观察不能代表生产并发性能。500 节点阶段仍观察到最长 215ms 主线程任务。图谱上限与未完成能力见 [图谱说明](graph.md)。

当前公开提交的自动检查以 GitHub Actions 实际结果为准；文档中的历史结果不能代替新提交检查，也不包括未启用的真实外部服务。

首次远端 CI 的后端结果为 596 通过、190 跳过、1 失败：SQLite 上两个并发重解析请求均被接受。修复使重解析和任务重试在检查活动任务前取得 SQLite 写事务，PostgreSQL 继续使用既有项目行锁；新增重试与重解析同时提交的用例。文档 SQLite 专项 24 通过、12 跳过；包含新用例的模板/文档 SQLite 与真实 PostgreSQL 17.9 专项最终 42 通过、2 跳过，临时容器已清理。新增测试首次留下待处理任务，干扰了共享 PG 夹具的后续用例，现已让该用例实际完成获准任务并验证历史修订；没有放宽业务断言。修复后的远端全量结果单独以 Actions 为准。
