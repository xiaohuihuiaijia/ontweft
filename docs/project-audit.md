# 项目审查与待审核事项

日期：2026-11-11。基线：`cefceff2`，企业 Beta 分支。优先修复可复现的错误和无用开销，保持轻核心、五个主入口及现有任务、权限和审批机制。

## 覆盖与方法

本轮逐模块通读后端自有生产实现、66 个前端生产文件、23 个开发/验证脚本、Java CDC 适配实现、部署配置和 17 份公共 Markdown。核对静态引用、动态注册、懒加载、公开手动入口及测试的独有覆盖；精读受影响测试并运行对应回归。27 个历史迁移、冻结函数、依赖锁文件保持不变，不把既往审查或生成清单说成新一轮逐行第三方审计。

只使用合成内容、隔离 SQLite/PostgreSQL 和本机模型替身。未读取客户文档、真实凭据或已有业务库，未调用付费模型。没有新增运行时依赖、表、迁移、常驻服务或平台层。审查不能保证“所有缺陷已消除”。

此前三轮审查、失败记录及原始计数保留在 [cefceff2 的审查记录](https://github.com/xiaohuihuiaijia/ontweft/blob/cefceff25753fdd389d9002b09add78b9beeb560/docs/project-audit.md)；具体历史验收继续见 [Beta 验证记录](beta-verification.md)，不与本批相加。

## 已修复的确定问题

| 问题与实际影响 | 最小修复 |
| --- | --- |
| 连续应用两个新增/更新文件，前一同步未执行时来源修订已改变，可能跳过第一批增量 | 同来源有待处理、运行或等待重试的同步时暂不应用新版本；沿用项目锁与任务状态，重复确认幂等，失败/取消仍可恢复 |
| 完整替换预览只比较上一个文件，漏掉此前新增/更新保留的记录 | 保留文件差异，另计算仍有效的来源记录撤回数量；确认前数量变动要求重新预览。撤回来源记录不等于删除业务对象 |
| 一次性匹配把被禁止的自引用也算成重复目标，与持续规则矛盾 | 先排除自身，再判断剩余目标是否唯一；不任意选择重复目标 |
| 动作表单搜索新对象后仍可能提交旧目标 | 开始新搜索时清除旧目标和预览，执行期间保持相关输入锁定 |
| 映射切换对象类型后残留旧类型身份键 | 同时重置字段映射和身份键；历史非法绑定明确待核对，不猜测替代键 |
| 文档列表逐条读取解析快照和任务，知识页读取正文后再丢弃 | 请求内批量读取必要元数据，知识页直接选择当前授权版本的列表字段；历史解析列表与权限预定位也不读取完整正文 |
| AI 提案列表读取全部候选、关系、定义和每个任务的大型中间结果 | 数据库计算候选数，只取摘要字段并批量提取公开进度；保留缺失值与显式空值区别，详情行为不变 |
| 首次模型回答已计费，后续格式修复因预算/网络失败时已知费用丢失 | 每个已收到的响应立即结算自己的预留；未知费用仍保留，不重复计入汇总，不绕过取消、租约和权限检查 |
| AI 浏览器脚本遗留临时数据库，两个脚本误判信号退出，响应等待可能绕过清理 | 保留独有用例，连接响应与点击的异常路径，等待自己的进程退出后仅清理本次临时目录 |
| 旧图谱样例把未规范化定义与正式模型比较，正常发布后也失败 | 使用已有模型定义规范化，不另造比较规则 |
| 部署命令漏配置文件或使用未安装依赖的系统 Python；文档描述与实际撤回行为不一致 | 直接修正文档原处、保留历史验收记录；模型计费与复杂 Office 限制同步到当前能力说明 |

执行前重新鉴权、并发版本检查、数据库一致性约束、任务租约及幂等处理不同的状态变化，继续保留。未删除公开 API、历史原件、来源贡献或已发布契约。

## 精简结果

没有发现可以证明“无公开用途、无动态入口且无独有覆盖”的整份生产文件或测试脚本，因此不为减少行数删功能。移除了列表路径不需要的正文/大型结果读取及逐行查询，整理旧脚本中的错误等待和清理行为；没有增加缓存服务或通用查询框架。前端现有懒加载和按需扩展保持不变。

同一合成 SQLite API 场景从 1 条增加到 8 条返回记录，文档列表 SELECT 次数由修复前 18→32 改为 18→18，AI 提案由 11→18 改为 11→11，已发布知识页由 17→24 改为 16→16。计数包含该场景的鉴权查询，不是请求延迟或全库吞吐承诺。
