# 首批使用者：四周验证计划

本轮目标不是承诺 Star 数量，而是找到 **5 名有实际资料治理需求的数据／AI 开发者**：至少 **3 名独立完成样例任务**，至少 **2 名尝试自己的数据或在一周后再次使用**。这些是待验证目标，不是已取得的结果。

只使用 GitHub 现有 Traffic、Issue 和一张匿名记录表。不增加埋点服务、增长后台、公共上传站点或社群矩阵。普通功能、生产部署和来源权限保持原有边界。

## 起点与问题判断

2026-11-13 读取的仓库基线：仓库创建于 2026-11-10；截至 11-12 的可见 Traffic 窗口有 **39 次页面访问、11 个独立访客**，当时为 **2 Stars、1 fork**。用户确认此前主要是上传 GitHub，尚未系统推广。

同窗口的 **282 次 clone / 95 个 unique cloners 不能当作 95 名用户**，也不能推出安装成功率。Traffic 的访问、克隆与 Star 口径不同，不能直接相除得到产品转化率；独立访客也不是确认的目标使用者。GitHub Traffic 仅保留近 14 天，按 UTC 记录，来源站点不包含 GitHub 自身和搜索引擎，见[官方说明](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository)。

当前证据支持优先检查三个环节：目标人群是否看见、是否理解具体用途、能否完成第一次有价值的操作。不能凭这组小样本断言产品没有需求，也不能把 README 改漂亮等同于解决曝光。

## 当前交付与待验证状态

截至 2026-11-13，固定预发布 [v0.1.0-beta.1](https://github.com/xiaohuihuiaijia/ontweft/releases/tag/v0.1.0-beta.1) 已公开，提供无 Key 体验镜像、实操视频及匿名拉取和容器验证记录；对应 `main` 的 [Source checks](https://github.com/xiaohuihuiaijia/ontweft/actions/runs/43415634478) 已通过。这些是维护者完成的工程验证，**外部用户能否独立完成、是否带自己的数据及一周复用仍待记录**。

本轮修正英文操作与中文界面标签的对应、反馈表单的双语提示，以及 Star 与发行订阅的混淆。Star 用于收藏或表示支持；订阅发行通知使用 Watch → Custom → Releases。简介自然说明 ontology、knowledge graph、knowledge management 与可选 knowledge base management；保留准确 Topics，不通过堆词或增加无关标签追求曝光。

GitHub 默认仓库搜索匹配名称、简介和 Topics；README 内容须用 `in:readme` 指定。真实 Stars 会影响部分排名和 Explore 展示，新手任务标签可能帮助真实贡献任务被发现，但没有已验证的 Trending 阈值或排名保证。依据：[仓库搜索](https://docs.github.com/en/search-github/searching-on-github/searching-for-repositories)、[Star](https://docs.github.com/en/get-started/exploring-projects-on-github/saving-repositories-with-stars)、[发行通知](https://docs.github.com/en/subscriptions-and-notifications/get-started/configuring-notifications)、[新手任务](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/encouraging-helpful-contributions-to-your-project-with-labels)。

搜索核对使用 `repo:xiaohuihuiaijia/ontweft` 限定本仓库，分别记录中文业务词、英文词组和 Topic 的命中状态；2026-11-13 更新简介后，`"knowledge base"` 从未命中变为命中，`知识图谱` 也能命中，均为完整搜索结果。这验证的是可检索性，不是全站排名。索引可能延迟，未刷新时留待核验，不反复改写简介。

贡献入口仅收录真实任务：现有样例的英文阅读说明和视频字幕。具体范围与验收见 [新手任务 #6](https://github.com/xiaohuihuiaijia/ontweft/issues/6)。发布任务不等于已有外部贡献，也不计为试用。

## 一个具体任务与一套事实资料

面向需要把产品规格、库存与适用条件连接起来的数据／AI 开发者。首屏、演示和试用邀请使用同一个三步任务：**查看产品与库存 → 查看关系条件 → 回查证据、修改条件并查看历史**。

| 可对外核对的内容 | 依据 |
| --- | --- |
| 本机合成产品体验，无需模型 Key；普通项目仍为空白 | 固定预发布 `v0.1.0-beta.1` 的体验镜像与随附资料 |
| 图谱和编辑器是真实应用，资料为合成内容 | [截图来源](images/README.md)、发行附件中的实操视频 |
| AI 可辅助起草，但候选需确认；未把演示当准确率评估 | [当前能力](enterprise-beta.md)、[验证记录](beta-verification.md) |
| 首批镜像只声明 `linux/amd64` 验证，其他架构未验 | 本次发行的构建与匿名拉取验证记录 |
| 复杂材料质量、持续负载与灾难恢复仍有边界 | [审查与待审核项](project-audit.md) |

对外材料应链接固定发行版本，说明谁适合试、能做什么、需要什么，以及当前真实限制。不要写“生产级”“开箱即用 AI”“几分钟保证部署成功”等未经验证的承诺。首页、视频与样例的名称、字段和操作必须对应同一版本。

## 四周动作，每周约两小时

每周固定分配：**40 分钟准备素材／发布、60 分钟沟通、20 分钟记录**。少做渠道，保留回复时间。发布前检查链接、镜像拉取与样例入口，未完成的产物不放进推广承诺。

| 周次 | 行动 | 当周要获得的证据 |
| --- | --- | --- |
| 第 1 周：先让人完成 | 发布固定可运行版本及 60–90 秒真实实操视频；由作者邀请 5 名符合画像的人试用，先让其自行操作，卡住后再协助 | 每人实际到达的步骤、是否需要帮助、首个卡点；不要用维护者自己的测试替代外部试用 |
| 第 2 周：一次中文场景分享 | 由作者在 V2EX「分享创造」发布一篇具体案例，指向同一运行入口；集中回复，并修复最常见的确定卡点 | 新试用者从何处得知、是否成功运行、具体问题是否解决；无反馈时先检查触达，不盲目加功能 |
| 第 3 周：一次英文作者分享 | 产品可直接试用后，由作者本人撰写并提交 Show HN，亲自解释为什么做、如何做和取舍 | 是否有人实际试用、追问或带自己的数据；只准备事实链接，不由 AI 代写、改写或自动发布 HN 文本 |
| 第 4 周：回访与收敛 | 回访首批使用者，确认一周后是否再用；按共同阻塞点做一次小修复，复核同一任务 | 是否达到 3 人独立完成、2 人真实数据或回访复用；若未达到，记录具体原因后调整，不扩张平台 |

Show HN 要求作品可供实际体验、降低试用障碍，并不允许拉票；[HN 发帖规范](https://news.ycombinator.com/newsguidelines.html)要求人类自行撰写、不发布 AI 生成或 AI 编辑的文本，也不自动发帖。此文件是内部执行记录，不是 HN 发帖稿。发布当天由作者重读[Show HN 说明](https://news.ycombinator.com/showhn.html)及对应社区规则。

### 每周汇总模板

| 周次／UTC 日期窗口 | 已邀请符合画像的人数 | 确认开始试用 | 独立完成 | 自带数据／一周复用 | GitHub views／unique | Stars（期末／本周净增） | forks（期末） | 最常见卡点与下一步 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待记录 | — | — | — | — | — | — | — | — |

同一人只计一次；“自带数据”和“一周复用”有交集时按人去重。GitHub Traffic 每周导出一次并写清日期窗口，不能把多周相互重叠的 14 天访问相加。Star 净增按同一仓库的周末存量减去周初存量，可能为负；Star 和 fork 只作为辅助观察，不等同于使用、留存或业务价值。

- **没触达到人**：改善具体渠道与邀请说明，不先添加功能。
- **看懂但跑不起来**：修复安装和首次进入问题，并请同一人重试。
- **能运行但不会完成任务**：改示例、空状态和关键文案，不先做通用引导平台。
- **完成后不再需要**：追问真实业务频率和缺口，再决定收窄定位或补一个必要能力。

试用反馈集中到[同一个 Issue 表单](https://github.com/xiaohuihuiaijia/ontweft/issues/new?template=first-experience.yml)。不批量发私信、不自动发帖、不买 Star、不请求他人刷票；仅在实际授权后发布内容。
