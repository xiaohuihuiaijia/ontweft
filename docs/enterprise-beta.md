# 精简核心与企业 Beta 改造

核心覆盖文件／PostgreSQL、可编辑本体、持续关系、授权图谱，以及可选模型连接驱动的文档理解与本体起草。默认只有**数据、本体、对象、图谱、设置**五个入口；文档理解进入数据工作台，模型连接位于设置，任务与审计沿用现有入口。没有新增插件平台、事件总线、审批引擎或搜索服务；不配置模型也能使用原有手工功能。

验收事实与未达标项见 [验证记录](beta-verification.md)，部署见 [自部署与恢复](deployment.md)。规模指标是验收目标，不能由源码存在推断已达标。

## 默认安装与固定扩展

`uv sync --locked --no-dev` 安装核心，包括本地文档格式读取、PDF 分页渲染和模型结构校验；不安装独立 OCR、GPU 或本地模型服务。业务页按需加载；扩展关闭时不注册对应 API、不显示入口、不执行该扩展的队列任务。历史数据和历史发布函数保留。

| 能力 | 固定配置 | 额外安装 |
| --- | --- | --- |
| 文件、PostgreSQL、本体、对象、图谱、文档理解 | 默认启用 | AI 起草另需管理员配置可用的模型 API |
| 知识页、文档／知识全文检索 | `knowledge` | 无额外服务；与文档理解保留不同权限和证据处理 |
| MySQL、MongoDB、Neo4j、RDF、HTTP、飞书 | `integrations` | `uv sync --locked --extra integrations` |
| 可信函数与 Action | `automation` | 仍需配置实际 Action 适配器；空适配器注册表不显示动作入口 |
| 既有 Docling 解析适配 | 文档解析任务显式选择 | 按目标平台安装和验证 `docling` 可选组；不作为 AI 主流程前置条件 |

扩展支持需按具体来源核对：底层 File/HTTP/Neo4j 适配器尚未提供可用于业务映射的完整字段描述，Mongo 目前仅声明 `_id`；能够发现或抽样不代表可以直接完成本体映射。默认 CSV/XLSX、文档与 PostgreSQL 接入不受此限制。

例如 `ONTOLOGY_EXTENSIONS=["knowledge","integrations"]`。配置在启动时读取，服务和 worker 必须一致。多个 `--extra` 可以并用；启用配置不能替代项目权限、字段权限和来源授权。停用飞书集成时不远程刷新授权，历史飞书材料不会因此获得公开访问权限。

会话 `/api/auth/me` 返回 `features`、`actions_available` 和 `model_approval`。已有公开扩展 API 路径保持不变，关闭扩展时不开放；没有用一个万能接口替换原有授权语义。

## 文档理解与 AI 本体起草

1. 管理员在“设置 → 模型连接”配置 OpenAI-compatible Chat Completions 服务地址、密钥、模型和用途。默认用途为常规提取与复杂理解／建模，可绑定同一个合适模型。文字、视觉、严格 JSON Schema、上下文、输出上限与价格分别配置；分别测试两种用途，测试仅发送合成文字与图片。
2. 在“数据 → 文档理解”上传材料，或在“本体 → AI 起草”选择已上传文件／已发现的 PostgreSQL 资源。业务要求留空为自动归纳，也可填写定向目标、选择页码和预算。先启动现有 worker；不新增第二套任务服务。
3. 对照原文编辑候选与差异，采纳到模型草稿，继续既有校验、审批、发布。文档实例在映射发布后另行确认导入；入口提前说明未满足的采纳或发布条件，发布后刷新可用状态；只有实例变化且映射已发布时，不再新增模型审批。数据库实例仍走确定性的采集映射，不逐行调用模型。

格式包括 PDF、DOCX、XLSX、PPTX、PNG／JPEG、CSV、文本／Markdown。上传流式保存并计算摘要，默认上限 **256 MiB**，可用 `ONTOLOGY_MAX_UPLOAD_BYTES` 调整。PDF 在本地逐页渲染，模型接收文字及页面图像；Office 以段落、工作表、幻灯片等逻辑单元定位，不把它们伪装成排版后的 PDF 页码。单个逻辑单元超过 32 张图片时，当前模型输入限制会阻止处理；不会静默丢图，可先导出分页 PDF 再接入。可直接读取的文字和单元格保留基础解析，复杂图文交给视觉模型。

每个选中页面都有处理进度，失败后沿用任务重试和已保存的页面结果。页面基础理解与业务需求分开；修改目标可复用同一文件版本及模型配置下的页面结果，变更模型配置形成新的缓存版本。全文模式处理全部选择范围，明确页码范围的任务只代表该范围。跨页拼接、密集表格、单位及条件仍需要结合来源复核，模型输出不自动成为事实。

长 PDF 的基础解析按 32 页保存本地批次；密集实例按片段提取并保留完整页面上下文。模型输出截断时，仅对受影响片段二分一次，仍超限则停止并保留已完成结果，不接受半份 JSON。视觉升级使用整页缩略图与重叠细节图，来源仍按真实页码定位。导入后的对象和关系可从图谱侧栏回到原文；读取来源记录与页面继续遵守各自权限。

文档实例使用稳定业务键、固定文档来源、既有快照及对象贡献账本。重复确认不重复创建；较窄的新任务不因字段缺失清空旧值，也不从部分解析推断删除。关系拥有独立文档贡献，移除人工支持或重算持续规则不会删除仍有其他来源支持的关系；冲突记录保留问题摘要。

已采纳的候选绑定同一模型变更集及其修订。草稿增加字段后，编辑候选可补齐必要文档映射并使旧校验、审批失效，原始生成定义仍保留；发布后不静默增加映射，未映射字段明确要求通过现有变更流程处理。

密钥由服务端使用现有加密机制保存，接口只返回是否已配置；普通成员仅看到已启用模型目录。每次请求前沿用当前权限、来源和配置修订检查。结构错误最多修复一次，鉴权失败停止，不退回旧密钥或切换供应商。费用根据管理员配置的价格预留；`enable_thinking` 只接受布尔值 `true`／`false`，显式启用思考时必须给出 `thinking_budget`，预留同时覆盖回答与思考。每次已收到的响应单独记录用量并结算对应预留；即使后续格式修复因预算或网络失败，已知费用也不会丢失或重复计费。未返回完整用量的请求继续保留自己的预留额，不记为免费。配置价格与供应商实际账单需由部署者核对。

接口保持小范围：`/api/model-connections` 管理与能力测试，`/api/documents/{id}/pages` 分页来源，`/api/ai/proposals` 创建、查看、编辑、采纳和导入。提案详情返回 `import_ready` 与 `import_block_reason`，只表达采纳／发布前置条件；实际导入仍重新检查权限、来源及当前模型版本。无新变更集的提案也绑定生成时的本体发布版；重复提交已成功导入的提案仍返回原结果。后台复用 `ai.propose` 任务；升级新增 `model_connections`、`ai_document_pages`、`ai_proposals`、`document_relation_contributions` 四张表，不重写历史发布模型或解析证据。升级前按部署指南备份数据库、资产和凭据加密配置。

## 文件版本与对象身份

1. 上传 CSV／XLSX 后，在首次对象采集前为每张表选择非空、唯一的业务键。列可以组合，行号只定位原件。
2. 在模型中确认字段和映射，必要时增加组合唯一键，完成校验、审核与发布，再采集。
3. 在同一来源的“文件版本与持续更新”上传新版。预览显示新增、变化、不变、“相对上一文件缺失”及“撤回来源记录”；后者按仍有效的来源记录计算，包含此前新增／更新模式保留的记录，不等于删除业务对象。应用后复用现有快照任务。
4. 默认“新增与更新”保留缺失记录。只有明确选择完整替换，并取得完整一致快照后，才撤回缺失记录的**该来源贡献**。其他来源、人工记录与原件历史保留。

文件历史按版本号游标分页，页面展示全部保留原件的合计字节数；未应用版本也保留。占用核对和孤儿隔离见 [部署维护](deployment.md)。

重复确认已应用版本返回原任务；过期来源修订拒绝覆盖。同一来源仍有待处理、运行中或等待重试的同步任务时，不能应用另一版本，避免尚未落地的增量被后续文件跳过。失败或取消后仍可按现有流程恢复。完整替换确认前若实际撤回数量变化，需要重新预览。无效或冲突记录保留原对象并在投影结果中列出，其他记录继续处理。结构改变需要新来源和明确映射，不把不完整采集或授权失效当作删除。

需要跨来源指向同一个对象时，先发布对象的组合唯一键，再在新来源映射的“身份绑定”选择该键。仅完整、精确的类型化值可以绑定；无匹配时创建对象，多来源属性仍由既有贡献裁决处理。数值键不经浮点数或 Decimal 默认精度截断。数值输入最多 1,000 位系数，固定展开的整数与小数部分各不超过 1,000 位，过大指数在展开前拒绝。

新模型默认采用规范键语义：日期规范化，带时区时间按同一 UTC 时刻比较，最多保留 6 位小数（微秒），超出精度明确拒绝而非截断。历史发布版未声明该语义时继续使用旧表示；在模型编辑器切换“键比较方式”，通过现有全量／增量校验后再发布。等价时间导致的重复键会阻止发布，不直接改写旧摘要。关联规则两侧必须使用兼容的键语义。

**旧来源迁移：** 已投影且基于行号的旧文件来源不能直接更换身份键。保留旧来源与引用，建立带业务键的新来源，选择已发布唯一键显式绑定已有对象。没有提供复杂历史对象合并或任意历史回滚。

## 持续关联

复用原来的关系匹配表单，选择已发布的关系及两侧兼容字段，可以一次性确认，也可以“保存为持续规则”。规则具有自己的关系贡献；手工关系和其他规则贡献继续保留。

对象写入在同一事务更新匹配索引并登记待重算对象，沿用现有任务租约与 fencing。只处理变化键涉及的对象；规则首次建立或修改时分批建索引。目标不唯一、贡献冲突或单目标关系已被其他支持占用时，暂停该记录并保留原支持。所有者撤权或模型不再兼容时暂停规则；暂停不会清空历史关系。

规则更新、启停、状态复用 `/api/relation-rules`，一次性匹配的原 API 继续可用。没有独立工作流系统。

## 约束与审批

- 组合唯一键采用数据库唯一索引，按项目、当前发布版和类型隔离。缺失／空值不占用唯一键，必填与身份绑定另行要求非空。
- 单目标关系在统一项目写入锁中验证，人工、一次性匹配、持续规则使用相同约束；发布校验复核现有关系基数。
- 超过 1,000 个对象时使用 `model.validate` 后台任务，每批 250 个对象；发布前按数据变化序号复核增量，避免整库校验长期占用项目锁。
- 校验崩溃保留检查点，可在现有任务中心重试；编辑草稿会使旧任务的修订失效。
- `ONTOLOGY_MODEL_APPROVAL=auto` 在 production 环境要求当前修订作者之外的审批者；本机开发默认单人。可明确设为 `single` 或 `separate`。
- 编辑改变当前修订作者并清除审批；界面提前说明异人模式下作者不能自行批准，服务端仍执行最终检查；发布时重新确认审批者仍有权限。Action 审批继续独立执行。

## 图谱与检索

画布仍最多 500 节点、1,000 条边。全库搜索使用现有授权检索 API，按需加入结果、分页展开邻居；可固定、拖动、收起节点并在本浏览器保存个人视图。恢复只保存的 ID、固定状态和坐标，重新向服务端确认当前可见对象，不在浏览器保留对象内容副本。编辑后刷新保留各展开来源和分页游标，仍可逐个收起邻域。

全文检索保留既有中文分词、全词项匹配、字段权限、模型修订和索引水位。实测发现 PostgreSQL RLS 下旧 `to_tsvector(...) @@ ...` 条件扫描整个租户字段表，因此复用现有派生表改为逐字段去重的规范化词项及等值 B-tree 索引。交互检索使用 `count_total=false`：只取一页及 `has_more`，不把未知总数显示为零；原 API 默认仍返回精确计数。新增当前对象排序索引，避免常见词查询为一页结果排序全部对象。PostgreSQL 17 使用事务级总时间预算，避免每条查询前再设置一次超时；旧 PostgreSQL 保留原有逐语句剩余预算。没有放宽 RLS、标记自定义 leakproof 函数或增加搜索中间件。[PostgreSQL 对 RLS 条件执行顺序的说明](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)

索引 worker 进入有界项目锁等待，持续读取不会让它一直跳过工作；超时保持任务待处理，不标记数据损坏。分词词典在 worker 启动时初始化，不在项目写事务中加载。

升级迁移会清空并重建**派生对象检索词项**，保留业务对象、原始证据和已发布模型。重建期间 API 标记索引更新中，界面提示结果可能不完整；启动 worker 后按原队列逐批恢复。文档检索仍是可选扩展，权限与证据语义不合并。

## 本轮边界

PostgreSQL 快照与 CDC 共用身份绑定、贡献裁决和关系重算。重建入口 `POST /api/cdc/streams/{id}/rebuild` 创建新采集代和不可变绑定，立即停用旧令牌／租约，保留旧事件、窗口、贡献历史和当前对象。新的完整快照证明提交前不替换业务基线；重新出现的业务键复用原对象，只有完整覆盖范围内明确缺失的贡献才撤回。页面可切换查看历史代。模型比较限于该来源的映射及相关类型语义，无关类型与显示标签修改不要求重采。

重建后的独立采集端需使用新通道、代次和令牌，以及新的 offset 文件、逻辑复制槽，详见 [CDC 操作说明](../integrations/debezium/README.md)。现有 10,000 事件／64 MiB 窗口预算保留；重建入口不等于超大快照／事务已经通过验收。没有重新实现采集协议。

来源测试、发现和抽样的网络 I/O 在数据库事务外执行，完成后重新检查权限与来源修订。最终对象快照投影保持整批提交，事务内复用不可变发布模型和来源身份查询；大批量写锁耗时仍需按实际接入量测量，不宣称已改为分批可见。

RDF／SHACL 交换、通用推理、向量及自然语言查询没有加入默认核心；用自然语言提出建模要求不等于开放任意查询或自动执行。首期 AI 输入限用户上传文件和 PostgreSQL，外部连接器继续保持原有授权语义。真实飞书员工导入／外发、独立 OCR、其他模型供应商及复杂材料的质量和费用需要分别验收；当前已验证范围见验证记录。
