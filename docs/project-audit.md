## 本次追加优化：七项均已落实具体改动

用户已授权直接优化并要求避免过度设计。以下替代原来的七项待决建议；没有增加运行时依赖、默认服务或通用框架。

| 原问题 | 当前实现与取舍 |
| --- | --- |
| CDC 无法重建基线 | 新采集代保留旧绑定、窗口、事件和贡献历史；旧令牌／租约失效，新完整快照提交前保持当前对象。只让相关映射／类型语义变化阻断，显示标签和无关类型不要求重采。来源页面支持重建及历史代查看 |
| 检索开销与性能目标 | PG 17 复用数据库事务超时，移除每条 ORM 查询前的额外超时 SQL；增加当前对象排序索引。图谱／全文交互只取一页及 `has_more`，原接口默认精确总数保持兼容。常见词与并发传播纳入同一个实测工具；索引以有界等待取得执行机会，避免持续读取导致饥饿；分词器在 worker 启动时初始化，结果见验证记录 |
| 数值展开与时间键语义 | 在共享边界限制 1,000 位数值，巨大指数在展开前拒绝。新类型用 UTC 微秒语义；旧类型默认保留旧语义，必须明确切换并通过已有对象的冲突校验再发布，不因编辑标签而偷偷升级 |
| 网络 I/O 与长写事务 | 来源测试／发现／抽样移到事务外，完成后重新鉴权和复核修订；快照投影复用事务内的不可变发布模型与身份查询。保留整批原子提交，不新增可见性版本层或检查点平台 |
| 登录限流不跨进程且不回收 | 现有数据库原子计数：账号／IP 与 IP 两级预算；成功清除账号桶，保留 IP 桶，过期记录有界回收。Compose 暴露既有可信代理地址配置；不加 Redis |
| 历史文件不可达且无法核对 | 游标分页可访问 100 条以前的版本，显示原件合计；离线维护命令按数据库引用核对实际占用，只隔离过期无引用目录并保留清单。全部已引用版本与证据保留，不自动永久删除 |
| 编辑后图谱不能按原分支收起 | 刷新保留各展开切片的成员与游标，按当前授权响应更新值和边；继续保留固定点与坐标，无额外全局状态系统 |

快照 1,000 条合成记录的 SQL 采样：首次投影总语句由 23,013 降至 20,012，读取由 11,012 降至 8,011；重复采集总语句由 15,013 降至 12,012。每批发布模型读取由 1,002 次降至 1 次，身份读取由 4,001 次降至 2,001 次。采样期间机器还有其他任务，耗时不作为严格前后对比或 10 万条接入性能证明。

升级新增三条迁移，未改历史迁移和已发布函数源码。本机旧 SQLite 提供显式升级命令，先生成一致性备份并核对外键；生产仍按已有备份—停服务—迁移—启动流程。使用与运维步骤见 [企业 Beta 核心说明](enterprise-beta.md)、[部署说明](deployment.md) 和 [CDC 采集说明](../integrations/debezium/README.md)。
