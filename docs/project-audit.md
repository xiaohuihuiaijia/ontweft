## 2026-11-13 核心建模闭环

| 确认的问题或缺口 | 本轮处理 |
| --- | --- |
| 同一关系的第二份文档依据未出现在详情；对象及历史可能返回撤权来源的摘录 | 按本页关系批量合并来源贡献，复用当前来源授权过滤摘录与定位；历史原件保留，图谱列表不额外读取其不返回的证据 |
| AI 起草缺少逐项建模理由，普通候选依赖手写 JSON | 同一建模调用返回业务问题、复用／新增理由和所选页或真实数据库字段依据；按模型实际差异核对，修改后标为生成时说明。候选复用类型化字段控件，业务键由选中字段取值 |
| 关系只有连线，无法正式表达适用条件 | 关系定义支持可选属性；对象和图谱复用同一编辑区。来源补缺值、相同值不变、不同值留作冲突；用户从报告打开关系确认，不增加自动优先级或人工边支持 |
| 关系条件变更无法回查 | 新增 `relation_revisions`，记录属性、直接证据和人工状态的修订及最终删除前状态。旧关系首次修改时记基线，不虚构完整的来源支持时间线 |
| 不同页面各自比较模型 JSON，旧默认值与别名可能误停 CDC | 服务端统一模型差异，校验扫描提供影响计数；类型支持别名，CDC 忽略展示信息及等价默认值，仍检查真实采集语义变化 |
| 导入阻塞项及后续操作不清晰 | 持久展示新增、更新、未变、阻塞数量与问题；关系冲突提供查看入口，原导入报告保持原样，重复导入不伪装为重试 |
| 关系编辑翻页丢草稿、保存提示被整页刷新卸载、手机字段竖排 | 沿用未保存状态保护；只刷新实例图数据，修正局部布局。旧自环与触屏测试保留，仅增加新行为覆盖 |

新增两条迁移：`ef311113a100` 创建关系修订表，`ef311113a200` 为旧提案增加默认空建模说明。没有改写历史迁移、冻结函数、原件或已有发布内容；没有新增运行时依赖、基础服务或通用平台。升级仍按部署文档先备份再迁移。

验证使用合成资料、独立 SQLite 与本机兼容模型替身，不读取客户 PDF、不使用真实凭据、不调用付费模型。已运行模型／CDC、关系、证据撤权、AI、前端及真实浏览器专项；源码清单和完整 Windows、Linux/PostgreSQL 回归以本轮 PR 与 [Actions](https://github.com/xiaohuihuiaijia/ontweft/actions/workflows/ci.yml) 为准，不将下方旧批次计数加到本轮。三个浏览器流程覆盖模型字段发布、自环命中、AI 依据与类型化编辑、发布导入、关系条件编辑、修订历史、原文回跳和手机布局。
