# 精简核心与企业 Beta 改造

本轮以文件／PostgreSQL、可编辑本体、持续关系、授权图谱为核心。默认只有**数据、本体、对象、图谱、设置**五个入口；任务与审计在设置中，采集进度仍在来源详情中。没有新增插件平台、事件总线、审批引擎或搜索服务。

验收事实与未达标项见 [验证记录](beta-verification.md)，部署见 [自部署与恢复](deployment.md)。规模指标是验收目标，不能由源码存在推断已达标。

## 默认安装与固定扩展

`uv sync --locked --no-dev` 安装核心。前端入口约 219 kB（压缩前构建文件），业务页按需加载；扩展关闭时不注册对应 API、不显示入口、不执行该扩展的队列任务。历史数据和历史发布函数保留。

| 能力 | 固定配置 | 额外安装 |
| --- | --- | --- |
| 核心文件、PostgreSQL、模型、对象、图谱 | 默认启用 | 无 |
| 文档、知识页、内容检索 | `knowledge` | `uv sync --locked --extra knowledge`；PDF 库在此组 |
| MySQL、MongoDB、Neo4j、RDF、HTTP、飞书 | `integrations` | `uv sync --locked --extra integrations` |
| 可信函数与 Action | `automation` | 仍需配置实际 Action 适配器；空适配器注册表不显示动作入口 |
| 复杂解析／OCR | `knowledge`，另配置解析任务 | 按目标平台单独安装和验证 `docling` 可选组 |

例如 `ONTOLOGY_EXTENSIONS=["knowledge","integrations"]`。配置在启动时读取，服务和 worker 必须一致。多个 `--extra` 可以并用；启用配置不能替代项目权限、字段权限和来源授权。停用飞书集成时不远程刷新授权，历史飞书材料不会因此获得公开访问权限。

会话 `/api/auth/me` 返回 `features`、`actions_available` 和 `model_approval`。已有公开扩展 API 路径保持不变，关闭扩展时不开放；没有用一个万能接口替换原有授权语义。

## 文件版本与对象身份

1. 上传 CSV／XLSX 后，在首次对象采集前为每张表选择非空、唯一的业务键。列可以组合，行号只定位原件。
2. 在模型中确认字段和映射，必要时增加组合唯一键，完成校验、审核与发布，再采集。
3. 在同一来源的“文件版本与持续更新”上传新版。预览显示新增、变化、不变、缺失记录；应用后复用现有快照任务。
4. 默认“新增与更新”保留缺失记录。只有明确选择完整替换，并取得完整一致快照后，才撤回缺失记录的**该来源贡献**。其他来源、人工记录与原件历史保留。

文件历史按版本号游标分页，页面展示全部保留原件的合计字节数；未应用版本也保留。占用核对和孤儿隔离见 [部署维护](deployment.md)。

重复确认已应用版本返回原任务；过期来源修订拒绝覆盖。无效或冲突记录保留原对象并在投影结果中列出，其他记录继续处理。结构改变需要新来源和明确映射，不把不完整采集或授权失效当作删除。

需要跨来源指向同一个对象时，先发布对象的组合唯一键，再在新来源映射的“身份绑定”选择该键。仅完整、精确的类型化值可以绑定；无匹配时创建对象，多来源属性仍由既有贡献裁决处理。数值键不经浮点数或 Decimal 默认精度截断。数值输入最多 1,000 位系数，固定展开的整数与小数部分各不超过 1,000 位，过大指数在展开前拒绝。

新模型默认采用规范键语义：日期规范化，带时区时间按同一 UTC 时刻比较，最多保留 6 位小数（微秒），超出精度明确拒绝而非截断。历史发布版未声明该语义时继续使用旧表示；在模型编辑器切换“键比较方式”，通过现有全量／增量校验后再发布。等价时间导致的重复键会阻止发布，不直接改写旧摘要。关联规则两侧必须使用兼容的键语义。

**旧来源迁移：** 已投影且基于行号的旧文件来源不能直接更换身份键。保留旧来源与引用，建立带业务键的新来源，选择已发布唯一键显式绑定已有对象。没有提供复杂历史对象合并或任意历史回滚。

## 持续关联

复用原来的关系匹配表单，选择已发布的关系及两侧兼容字段，可以一次性确认，也可以“保存为持续规则”。规则具有自己的关系贡献；手工关系和其他规则贡献继续保留。

对象写入在同一事务更新匹配索引并登记待重算对象，沿用现有任务租约与 fencing。只处理变化键涉及的对象；规则首次建立或修改时分批建索引。目标不唯一、贡献冲突或单目标关系已被其他支持占用时，暂停该记录并保留原支持。所有者撤权或模型不再兼容时暂停规则；暂停不会清空历史关系。

规则更新、启停、状态复用 `/api/relation-rules`，一次性匹配的原 API 继续可用。没有独立工作流系统。

## 约束与审批

- 组合唯一键采用数据库唯一索引，按项目、当前发布版和类型隔离。缺失／空值不占用唯一键，必填与身份绑定另行要求非空。
- 单目标关系在统一项目写入锁中验证，人工、一次性匹配、持续规则使用相同约束；发布校验复核现有关系基数。
- 超过 1,000 个对象时使用 `model.validate` 后台任务，每批 250 个对象；发布前按数据变化序号复核增量，避免整库校验长期占用项目锁。
- 校验崩溃保留检查点，可在现有任务中心重试；编辑草稿会使旧任务的修订失效。
- `ONTOLOGY_MODEL_APPROVAL=auto` 在 production 环境要求当前修订作者之外的审批者；本机开发默认单人。可明确设为 `single` 或 `separate`。
- 编辑改变当前修订作者并清除审批；发布时重新确认审批者仍有权限。Action 审批继续独立执行。

## 图谱与检索

画布仍最多 500 节点、1,000 条边。全库搜索使用现有授权检索 API，按需加入结果、分页展开邻居；可固定、拖动、收起节点并在本浏览器保存个人视图。恢复只保存的 ID、固定状态和坐标，重新向服务端确认当前可见对象，不在浏览器保留对象内容副本。编辑后刷新保留各展开来源和分页游标，仍可逐个收起邻域。

全文检索保留既有中文分词、全词项匹配、字段权限、模型修订和索引水位。实测发现 PostgreSQL RLS 下旧 `to_tsvector(...) @@ ...` 条件扫描整个租户字段表，因此复用现有派生表改为逐字段去重的规范化词项及等值 B-tree 索引。交互检索使用 `count_total=false`：只取一页及 `has_more`，不把未知总数显示为零；原 API 默认仍返回精确计数。新增当前对象排序索引，避免常见词查询为一页结果排序全部对象。PostgreSQL 17 使用事务级总时间预算，避免每条查询前再设置一次超时；旧 PostgreSQL 保留原有逐语句剩余预算。没有放宽 RLS、标记自定义 leakproof 函数或增加搜索中间件。[PostgreSQL 对 RLS 条件执行顺序的说明](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)

索引 worker 进入有界项目锁等待，持续读取不会让它一直跳过工作；超时保持任务待处理，不标记数据损坏。分词词典在 worker 启动时初始化，不在项目写事务中加载。

升级迁移会清空并重建**派生对象检索词项**，保留业务对象、原始证据和已发布模型。重建期间 API 标记索引更新中，界面提示结果可能不完整；启动 worker 后按原队列逐批恢复。文档检索仍是可选扩展，权限与证据语义不合并。

## 本轮边界

PostgreSQL 快照与 CDC 共用身份绑定、贡献裁决和关系重算。重建入口 `POST /api/cdc/streams/{id}/rebuild` 创建新采集代和不可变绑定，立即停用旧令牌／租约，保留旧事件、窗口、贡献历史和当前对象。新的完整快照证明提交前不替换业务基线；重新出现的业务键复用原对象，只有完整覆盖范围内明确缺失的贡献才撤回。页面可切换查看历史代。模型比较限于该来源的映射及相关类型语义，无关类型与显示标签修改不要求重采。

重建后的独立采集端需使用新通道、代次和令牌，以及新的 offset 文件、逻辑复制槽，详见 [CDC 操作说明](../integrations/debezium/README.md)。现有 10,000 事件／64 MiB 窗口预算保留；重建入口不等于超大快照／事务已经通过验收。没有重新实现采集协议。

来源测试、发现和抽样的网络 I/O 在数据库事务外执行，完成后重新检查权限与来源修订。最终对象快照投影保持整批提交，事务内复用不可变发布模型和来源身份查询；大批量写锁耗时仍需按实际接入量测量，不宣称已改为分批可见。

RDF／SHACL 交换、通用推理、向量及自然语言查询没有加入默认核心。未来自然语言能力应复用现有受限结构化查询。真实飞书员工导入／外发和复杂 OCR 需要各自配置及验收，本轮不以替身服务宣称它们已通过。
